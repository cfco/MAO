## 修复内容

1. **顶层词表合并 + Runner 词收集**（`agent/tools/shell_safety.py`）
   - `_POSIX_DANGEROUS_SET` 扩员：+mkswap/sfdisk/parted/wipefs/poweroff/halt；新增
     `_POSIX_DANGEROUS_PREFIXES=("mkfs",)` 兜 `mkfs.ext4` 类变体（精确匹配拦不住；
     不放 `mk` 前缀——mkdir/mkfifo 是正常命令）。
   - 顶层循环 `_CMD_DANGEROUS_SET` → `_is_dangerous_word()`（集合 + 前缀，顶层与内联
     正文共用同一判定，防两处口径漂移）。
   - `_command_heads` 增收 `_runner_targets(segment)`：xargs 的第一个非选项词、find 的
     `-exec/-execdir` 后词、`-delete`（按 rm 拦）。
2. **超时杀进程树**（`agent/tools/builtin.py`）
   - `subprocess.run` → `subprocess.Popen` + `communicate(timeout=…)`；三处 spawn 全带
     `start_new_session=True`（POSIX pgid==pid 是 killpg 的前提；Windows 上该参数被忽略、
     杀树走 taskkill，不依赖它）。
   - 新增 `_kill_process_tree()`：POSIX `os.killpg(proc.pid, SIGKILL)`（用 pid 不用
     getpgid——直接子进程可能已回收，组在就能杀）；Windows `taskkill /F /T /PID`；
     两条路都失败退 `proc.kill()`。杀后二次 `communicate` 回收输出防僵尸/管道悬挂。
   - 代价（已知）：子进程不再随 bridge 的 Ctrl+C 一起中断——长驻服务里反而更安全。
3. **工具描述平台感知**：`_shell_flavor()` 按 `sys.platform` 返回"Windows cmd 语法"/
   "POSIX shell 语法"，注册描述与 docstring 都接上。做成函数非常量：测试可 monkeypatch
   平台在同一进程里验两个分支。
4. **杂项**：mutation_check 头注释双平台化；新增 `.gitattributes`（`* text=auto eol=lf`）。

## 测试（tests/test_platform_compat.py，41 条，全离线）

- 风味函数两分支（monkeypatch 平台，Windows/Ubuntu 都真跑两个分支）+ 描述接上风味；
- POSIX 顶层危险命令 18 条 parametrize 全拦 / 正常命令 18 条全放行（含 find 单管道、
  `-exec grep`、`chmod +x` 等易误伤样本）；
- 真实子进程杀树验尸：父母 python spawn sleep 60 孩子并落 pid，shell_timeout=3s 跑之，
  超时后轮询验孩子死亡（Windows OpenProcess / POSIX /proc stat 查 Z 态 / 无 /proc 退
  os.kill 探活，两侧都不 flaky）；
- spawn 必须带 start_new_session（杀树前提）。

## 顺手修掉的两个门禁自身问题

  `fut.result(timeout=...)` 那行 → 变异后仍通过。已补调用路径断言（假 session/loop +

## 已知边界（有意不做）

- `chmod -R 000 /`、`chown -R`、`mv x /dev/null` 不拦：chmod/chown/mv 是正常开发命令
  （`chmod +x` 在 Linux 是常规操作），按首词拦误伤面大于收益；黑名单自我定位是"命令
  卫生"不是沙箱，硬隔离靠 OS/容器层。
- `systemctl`/`iptables` 不拦：属系统状态管理非数据破坏，且开发场景可能合法使用。
