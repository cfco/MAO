# 多功能智能体 - 架构方案 v2

> 2026-09-21 定稿。目标：**多智能体协作系统**——多个免费/较慢/较弱模型分工协作，"三个臭皮匠顶个诸葛亮"。
> 双形态入口：网页/App 对话助手 + 本地自动化工具，可接入 MCP 和 Skill。

> ⚠️ **本稿为 v2 设计稿，不是行为基准。** §0/§1 保留立项时的设计取舍（含当时规划的
> CLI/Web 选主形态），供理解"为什么这么设计"。**权威基准见
> [REQUIREMENTS.md](../REQUIREMENTS.md)**。
> 2026-09-22 最新收敛：项目只保留 **bridge 单一路线**（外部 AI 当主），CLI/Web 选主、
> 内部 Agent Loop、持久会话、固定流水线、事件流（stream）均已移除，MAO 侧**无状态**；
> 下文 §2.3/§2.4/§3 已同步为收敛后的当前态。

## 0. v2 核心变更（相对 v1）

1. **单一 LLM → 智能体池**：`config.yaml` 配置多个 API 智能体（免费档、本地 Ollama 均可），每个是一条 `AgentProfile`。
2. **主智能体由启动方式决定**：
   - **外部智能体启动/驱动本项目** → 该智能体就是主。项目通过 `bridge` 协议（stdin/stdout JSON 行）给它提供：本地工具执行、MCP 工具、Skill、以及把池内任何模型当无工具"纯工人"调度的能力。
   - **CLI / Web 直接启动** → 用户从智能体池中交互式选择一个当主，其余全部自动成为子智能体（工人）。
3. **协作模式（第一版）**：
   - `swarm`（默认）：`ask_worker`（单派子任务）与 `ask_workers`（同一子任务并行派多人，多方案对比/交叉验证）做成**主智能体的工具**，主智能体在 Agent Loop 里自主决定拆解、派工、汇总时机。
   - `solo`：单模型直接跑（退化模式，工人池为空时自动落入）。
4. 工人=纯文本执行器（不挂本地工具）：免费模型 function calling 支持参差不齐，纯文本最稳也最安全；本地工具只由主智能体掌握。

## 1. 总体架构

```
┌────────────────────────────────────────────────────┐
│                     启动入口层                        │
│  外部智能体(bridge协议) │ CLI │ Web UI                │
│  → 外部智能体=主       │ → 用户选主 │ → 用户选主       │
├────────────────────────────────────────────────────┤
│              主智能体（Agent Loop + 工具）             │
│   内置工具 / MCP 工具 / Skill / ask_worker(s) 工人池   │
├──────────────┬──────────────┬──────────────────────┤
│  智能体池配置   │   工具系统     │    Skill 机制          │
│  AgentProfile │  统一注册表    │   SKILL.md 按需加载     │
│  name/base_url│  内置+MCP      │   脚本执行             │
│  /api_key/mdl │               │                       │
└──────────────┴──────────────┴──────────────────────┘
        │ ask_worker / ask_workers（并行、跨模型）
        ▼
   子智能体们（纯文本执行器，免费/慢/弱模型均可）
```

## 2. 核心设计决策

### 2.1 智能体池（AgentProfile）
- 每个条目：`name`（唯一，派工时引用）/ `base_url` / `api_key` / `model` / `note`。
- 走 OpenAI 兼容协议，免费档（GLM-flash、Kimi 免费额度、Groq 免费档）与本地 Ollama 都能进池。
- 主智能体只是池中被选中/被指定的那一条；选中后其余条目自动成为工人。

### 2.2 协作机制
- 工人不带本地工具（纯文本进出），主智能体带全部工具——工具权集中，安全且兼容差模型。
- `ask_workers` 内置线程池并行，单工人失败不影响整体，失败信息随结果回灌。
- 提示词引导主智能体：复杂任务拆解派工、同一关键问题多人对比取共识、工人的结果要审查后采信。

### 2.3 bridge 协议（外部智能体 = 主智能体，唯一路线）
- `python -m agent bridge`：stdin 每行一个 JSON 请求，stdout 每行一个 JSON 响应（UTF-8），
  一问一答、串行处理。**stdout 只放 JSON 行**，诊断/警告一律走 stderr，调用方可直接按行 `json.loads`。
- 指令集（2026-09-22 收敛后）：
  | 类别 | 指令 |
  |------|------|
  | 握手/清点 | `ping` / `list_agents` / `list_tools` |
  | 派工预检 | `health`（各子 AI 冷却/当日隔离/能力标签快照） |
  | 本地能力 | `call_tool` / `load_skill` / `run_skill_script` |
  | 池内模型当子 AI | `ask` / `ask_many`（结构化逐工人结果）/ `ask_vote` / `run_review`（评审团） |
- 任何能起子进程、能读写行的智能体框架都能驱动本项目。
- 已移除的历史指令：`run_pipeline`、`new_session`/`chat`/`list_sessions`/`session_tools`/
  `close_session`、`cancel_tool`、`stream` 参数（详见 docs/外部主接入指南.md §3.4）。

### 2.4 其余（LLM 协议 / 工具系统 / Skill）
- **LLM 协议**：OpenAI 兼容；统一 `LLMClient`（超时、错误分类、指数退避、畸形响应归一）。
  工人走纯文本 chat，不再依赖 function calling。
- **工具系统**：统一 `Tool` 接口 + 注册表；内置 shell/文件、MCP、Skill 工具同构。
  文件工具活动范围 = 项目根 + `tools.workspace` 登记的额外目录（默认仅项目根；
  越界拒绝、覆盖前自动留档 `data/backup/`）。
- **MCP**：stdio/HTTP 双传输、断线自动重连；连接按配置**进程内共享**（引用计数）。
- **Skill**：SKILL.md frontmatter + 按需加载 + 脚本执行。
- **免费节点容错**：分类重试、连续失败节点冷却、**当日失败隔离**（`ModelHealth`，档案
  `data/model_health.json`）。"连续多运行日失败自动改 `.env.example` 下线"已移除，
  去留判断权交给外部主（`health` 指令）。
- **运行模型**：MAO 侧无状态——无内部 Agent Loop、无会话持久化（历史 JSONL/隔离区清理/
  会话级工具白名单均已移除），上下文由外部主自持。

## 3. 目录结构（2026-09-22 收敛后当前态）

```
MAO/
├── agent/
│   ├── __main__.py         # CLI 入口（仅 bridge 一条路线）
│   ├── bridge.py           # 外部智能体驱动协议（无状态一问一答）
│   ├── config.py           # 智能体池 AgentProfile + 协作配置 + 分层 env 加载
│   ├── skills_manager.py   # Skill 机制
│   ├── core/
│   │   ├── llm.py          # LLM 适配层（超时/分类/退避/畸形响应归一）
│   │   ├── orchestrator.py # 工人池 WorkerPool：ask / ask_many(结构化) / vote + health 预检
│   │   └── health.py       # ModelHealth：当日失败隔离（进程内共享单实例）
│   └── tools/ （base / builtin / mcp_client；builtin 支持 tools.workspace 多根越界判定）
├── tests/                  # 离线测试（ruff + pytest 门禁）
├── skills/  data/  docs/  config.yaml  .env.example  README.md  REQUIREMENTS.md
```

已随收敛移除：`agent/core/agent.py`（内部 Agent Loop）、`pipeline.py`（固定流水线）、
`events.py`（三入口事件 schema）、`session.py`（会话落盘）、`web/`（FastAPI+SSE 前端）。

## 4. 里程碑

| 阶段 | 交付物 | 验收 |
|------|--------|------|
| M1 | Agent Loop + 内置工具 + CLI（solo） | 命令行跑通带工具调用对话 |
| M2 | MCP + Skill 机制 | 挂 MCP server、加载技能 |
| M3 | Web UI + 主智能体选择 | 浏览器对话、看到协作过程 |
| M4 | **智能体池 + swarm 协作 + bridge 协议** | 多个免费模型协作完成任务；外部智能体可驱动 |
| M5 | 打磨 | 固定流水线策略（起草-评审-修订）、投票汇总、配置引导 |
