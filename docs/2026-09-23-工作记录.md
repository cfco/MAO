# 2026-09-23 工作记录：配置重构二期 —— .env 全配置化 + 模型清单独立 + 恢复自动下线

## 一、需求（用户原话要点）

> 我的配置文件之前改的不好，现在要重新弄，把配置文件全部写到 .env 文件，需要
> 屏幕（应为"模型"）的模型名称使用另外的文件来处理。还是需要保留，如果 7 天都
> 使用不了，标记删除模型。这里的 7 天是指的 7 个实际工作日。没运行项目的都不算。

拆解为三条：
1. 全部配置值写进 `.env`（端点 / KEY / LLM 参数 / 协作参数 / 工具参数）。
2. 所有模型名称放到单独文件 → `model_registry.txt`（随仓库维护、进 git）。
3. **恢复**（上一轮被移除的）自动下线机制：连续 7 个"运行日"都调用失败 → 在
   `model_registry.txt` 给该模型加 `#` 标记下线；"运行日"= 程序实际启动工作的天，
   没运行项目的那天既不计入、也不打断连击。

## 二、布局定稿

| 文件 | 职责 | 进出 git | AI 可否改 |
|---|---|---|---|
| `config.yaml` | 纯结构骨架，全部 `${VAR}` / `${VAR:-默认}` 引用，无真实值 | 是 | 是 |
| `.env` | 全部配置值（ENDPOINT / KEY / LLM/协作/工具参数） | **否**（.gitignore 排除） | 是 |
| `model_registry.txt` | 全部模型名（`NODE_A_MODELS` / `NODE_B_MODELS` / `LLM_MODEL`） | 是 | 是（自动下线改写它） |
| `.env.example` | **已删除**（git 有备份；职能被上述两份文件承接） | —— | —— |

加载优先级：shell 环境变量 > `.env` > `model_registry.txt`。
双向守卫：registry 绝不出现 `*_KEY` 行（测试守着）；`.env` 混入 `*_MODEL(S)` 时
`[配置分层提醒]` 按名告警（不回显值）。

## 三、代码改动

### agent/model_registry.py（新建于上一轮，本轮核对）
- `load_model_registry()`：KEY=VALUE 行式解析（注释行跳过）→ 注入 os.environ 的基础层。
- `retire_model(env_var, model)`：给指定变量行的模型加 `#`，幂等，原子写盘。

### agent/config.py
- `load_config()` 基础层改为 `ROOT / "model_registry.txt"`（替换 .env.example）；
  mtime 缓存变量 `_cfg_cache_example_mtime` → `_cfg_cache_registry_mtime`。
- 分层守卫改向：`.env` 中出现 `*_MODEL` / `*_MODELS`（模型清单变量）才告警；
  `.env` 允许端点/KEY/参数任意配置值（不再限定只放 KEY）。
- `_load_dotenv()` 支持行内注释剥离：值里"空格+#"起头的部分视为注释
  （`TOOLS_SHELL_TIMEOUT=120 # 秒`），不误剥 `NODE_A_MODELS=#m-one` 的屏蔽标记。
- `Config` 新增 `retire_days`（collaboration.retire_days，默认 7，最小值 1）与
  `model_registry_path`（环境变量 `MAO_MODEL_REGISTRY_FILE` 可覆盖，测试隔离用）。
- 文档字符串全面更新（v4）。

### agent/core/health.py —— 恢复自动下线
- `ModelHealth.__init__` 增加 `registry_path` / `retire_days` 参数。
- `record_failure()` 恢复判定：最近 `retire_days` 个运行日全部落在该模型失败日
  → 置 `disabled` 标记 → 锁外调用 `_retire_in_registry()` 给 registry 加 `#` →
  返回 stderr 提示文本（调用方打印）。
- `_ensure_loaded()` **不再预记"今天"为运行日**：运行日由记账决定（record_failure /
  note_active 记哪天，哪天算）——否则测试注入历史失败日会混入"今天"，且第 7 个
  失败日当天无法立即下线（要等第 8 天）。
- 幂等：已 `#` 下线的模型再失败不重复改写、不重复提示；`LLM_MODEL` 兜底行不自动动。
- `get_health()` 扩展签名传 registry_path / retire_days（首次创建生效，共享语义不变）。

### agent/core/orchestrator.py
- WorkerPool 默认构造 `get_health(cfg.model_health_path, cfg.model_registry_path, cfg.retire_days)`。

### agent/core/parallelism.py（本轮新建）

## 四·补、CI 失败修复（push 后 35808328433 红灯）

  配置类变量全部插值为空 → 断言失败。同文件 `test_config_referenced_vars_are
  _covered_by_registry_and_env` 早已有 `.env` 缺失时 `pytest.skip` 的保护（CI 日志里
  的 1 skipped 就是它），而本用例漏了，处理不一致。
- 修复：`test_filling_registry_and_env_activates_llm_section` 开头加同样的
  `if not DOTENV.exists(): pytest.skip(...)`（含注释说明原因），与既有用例保持一致。
- 验证：模拟 CI（临时删 .env）契约测试 2 个 skip 其余全过；恢复 .env 后全量
