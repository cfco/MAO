## 六、续做：站点门粒度根因 + P2 小批（2026-10-16）

- **门粒度（本轮最大的一条结构性问题）**：`LLMClient` 拆出 `chat_once()`（单次尝试），派工的重试环
  挪到 `WorkerPool._attempt_with_retry` 在**门外**跑；延迟探测也改调 `chat_once`（语义本就是

  `timeout×(1+retries)+退避` 量级（实测：同站第二个工人白等 1.55s）。

  每模型重试（它们验的是"换模型"，重试次数是正交维度）。

### 撤回的一条 P2（我自己报的，实测不成立）

审计报告前一版写："`retire_model` 用 `\n".join` 写回，autocrlf 用户克隆后一次自动下线会把整文件
转成 LF、git 显示全文件改动"。决定性实验（在 `core.autocrlf=true` 的干净克隆里真跑 `retire_model`）
证明**不成立**：`Path.write_text` 以文本模式打开，默认 `newline=None` 会把 `\n` 译成 `os.linesep`，
所以 Windows 上写回仍是 CRLF（该文件 CR 字节 32→33），`git diff --numstat` 只有 `2 2`，
就是被改的那一行。**没有新增 `.gitattributes`**（写了反而会把用户工作树悄悄改成 LF，收益为零）。
教训：`grep -c $'\r'` 在 Git Bash 里数不出 CR，必须 `tr -cd '\r' | wc -c` 才可信。
