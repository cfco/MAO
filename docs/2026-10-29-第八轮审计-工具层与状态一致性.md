# 第八轮审计（2026-10-29）：工具层密钥外流、shell 包装绕过、状态一致性与契约收敛

驱动方式：4 个只读子代理分区扫描（编排/LLM 层、状态与闸门层、配置与工具层、工程化与文档层）
→ 主代理逐条回读源码核实 → 按 P0→P1→P2 分批修 → 每批跑 `pytest` + 变异门禁验证。
子代理共报 60 余条，核实后剔除 2 条误报（见"剔除的误报"），其余分三批落地。

## 一、P0：工具层把凭据送出去的四条路

### 1. `type .env` 绕过 `read_file` 的密钥守卫，且 shell 输出不过脱敏

- **问题**：`read_file` 早就拒绝读出 `.env`，但 `run_shell` 侧没人管——`type`/`cat`/`more`
  的首词都不在 cmd 与 POSIX 两张危险词表里，而 shell 内置命令必然回落 `shell=True`
  （`builtin.py` 的 `FileNotFoundError` 分支）。一条 `type .env` 就把全部池 key 读进
  stdout，原样外发给外部主（另一个模型）。
- **定位**：`agent/tools/builtin.py:363-374`（输出拼接处不过 `redact`）+
  `agent/tools/shell_safety.py`（无按文件名的拦截）。
- **修法**：① `shell_safety._check_secret_file_access`：命令正文里出现密钥文件名一律拒
  （读写双向都拦——覆写 `.env` 等于把 endpoint 改成外部地址，下一次加载把凭据发出去，
  且留档机制故意不给密钥文件留底、不可回滚）；文件名口径与文件工具共用
  `_is_secret_basename`（`.env`/`.env.*`、以 `secret`/`credential` 开头；`.env.example`
  及其备份除外）。② `run_shell` 的 stdout/stderr 先过 `mask_secrets` 再截 8000/4000。
  ③ `write_file`/`append_file` 补上写入侧守卫。④ bridge 的 `call_tool`/`load_skill`/
  `run_skill_script` 出口统一 `mask_secrets`（覆盖 MCP 远程工具与技能脚本这些"源头不掩码"的正文）。
- **回归**：`tests/test_audit8_security.py` 第 3、4 节 + `tests/test_audit8_fixes.py`
  第 8 节；锚点 M79–M81、M99。

### 2. `"cmd" /c "del x"` 这类包装把破坏命令留在内层不被扫描

- **问题**：Runner 剥壳只认 `cmd /c` 的裸拼写（正则 `^\s*cmd(?:\.exe)?\s*/[ck]\s+`），
  于是外层引号、全路径（`C:\Windows\System32\cmd.exe /c del …`）、`%COMSPEC%`、
  POSIX 的 `sh -c "rm -rf x"` 全部把首词解析成 `cmd`/`sh`，内层正文不再递归——整条黑名单形同虚设。
- **定位**：`agent/tools/shell_safety.py:54`（包装正则）+ `_head_word`/`_command_heads`。
- **修法**：新增 `_norm_head`（剥引号、剥 `^` 转义、剥 `%VAR%` 两侧百分号、取 basename、
  去 `.exe/.com`）与 `_unwrap_runners`：按归一后的命令词识别 Runner，把正文展开成一段段
  命令再走一遍全部扫描（深度限 4 层，`cmd /c "python -c …"` 的内联正文也因此进得了
  第②层）。PowerShell 分支改为"任一段的命令词是 powershell/pwsh 就扫正文"，
  不再只看 `heads[0]`。旧的 `_CMD_WRAPPER` 常量随之下线（无引用后不留死代码）。
- **回归**：`tests/test_audit8_security.py` 第 1 节（含"包装里的内联代码要扫到高危 API"、
  反向不误杀 `cmd /c "dir"` / `sh -c "ls -la"`）；锚点 M82。

### 3. `echo a>..\..\evil` 少一个空格就写出项目根

- **问题**：重定向越界检查的正则要求操作符前有空白（`(?:^|\s)`），不留空格的写法整条不匹配，
  而含 `>` 的命令一律走 `shell=True` 真写盘。
- **定位**：`agent/tools/shell_safety.py:121`。
- **修法**：把前缀约束换成否定后查 `(?<![<>=!])`（不再要求空白，同时避开 `=>`/`>=`/`->`
  这类运算符），并保持"引号内字面量不误伤"（`_mask_quoted` 那条通道不变）。
- **回归**：`tests/test_audit8_security.py` 第 2 节；锚点 M83。

### 4. 异常文案不抹 URL 的 userinfo

- **问题**：`redact._URL_QUERY` 要求 URL 里有 `?` 才命中，`https://user:pwd@host/v1`
  整段原样进 stdout 与工人 prompt——而"底层异常回显请求 URL"正是这条通道的主要来源。
- **定位**：`agent/core/redact.py:17`。
- **修法**：新增 `_URL_USERINFO`，只抹 `scheme://` 到第一个 `@` 之间，host/path 保留
  （排障要看的恰恰是 host）。顺带把"掩码"与"截断"拆成两个出口：`mask_secrets`（不截断，
  给工具正文）与 `safe_error_text`（截 200，给错误文案），共用同一份 `_SECRET_PATTERNS`。
- **回归**：`tests/test_audit8_security.py` 第 5 节；锚点 M84。

## 二、P1：状态一致性与对外契约

1. **自动下线一次性永久失效**。`record_failure` 先落 `entry["disabled"]` 再去改
   `model_registry.txt`；而 `retire_model` 遇 `OSError` 或并发写者打架耗尽重试会返回
   `RETIRE_MISSING` ⇒ 档案说"已下线"、清单里模型照旧在派工，且 `if not entry.get("disabled")`
   让它**永远不再重试下线**。改成"`disabled` 只在下线真的写上之后落"。锚点 M85。
2. **发现器把别人的清单叠到本站**。`KiloAdapter.fetch` 收 `base_url` 却写死全局网关，
   任何标 `discovery: kilo` 的站都会把 kilo 的公开免费清单（不可信远端字符串）叠进本站 env
   与运行池；同时 `retired` 侧没有"归本适配器管"的过滤 ⇒ 人工加进 registry 的付费模型
   因为"不在线"被判下架、被从 env 与池里摘掉。加 `Adapter.host` / `free_marker` 两个属性 +
   `_owns_station` / `_manages` 判定（按属性读取，测试里的假适配器不继承 `Adapter` 也不会
   AttributeError），并对远端 id 做字符白名单（含逗号=往 env 注入多条模型）。锚点 M90–M92。
3. **热同步换池打穿"永不抛异常"的派工接口**。`_fallback_target` 先 `n in self.profiles`
   再 `self.profiles[name]`，而 `sync_free_nodes` 在锁内**整本替换**该 dict ⇒ 两次取值之间
   插队就 KeyError，从 `_call_result` 的兜底 `except` 里再抛出去。改为一次快照 + `.get()`；
   `pick()` 里的 `_has_tags` 同病同修。锚点 M93。
4. **投票平票由线程完成顺序决定**。`_wait_gather` 按 `FIRST_COMPLETED` 插入结果字典，
   `tally` 的插入序随之漂移，`max(tally.items(), key=票数)` 平票时取先出现者 ⇒ 同一批选票
   两种完成顺序选出不同方案，与代码反复声明的"确定性编号"矛盾。改为
   `key=lambda kv: (kv[1], -kv[0])`（编号小者胜）。锚点 M94。
5. **`select_best` 解析阈值却不参与判定**。`th` 只被拼进摘要字符串，`_invalid` 收下不用 ⇒
   调用方无法从返回值区分"过半共识"与"1/3 也算最高票"。改为未达阈值返回 `None`、废票写进
   摘要、空候选前置短路（旧写法照样向全体投票人广播一轮"候选方案：(空)"，白烧额度）。锚点 M95–M96。
6. **空正文以哨兵混进候选池**。`_call_result` 把空 `content` 换成 `"(空回复)"`，于是
   `collect()` 那句"空回复的工人不进结果"（按 `answer` 真值过滤）永不生效，空答复会作为候选
   进入投票、还能被投中。结构化 `answer` 恢复真空串，空提示挪到展示层 `render_answer`
   与 bridge 的文本拼接。锚点 M97。
7. **三外壳的兜底形状不齐**。`bridge` 的 serve 循环每条指令都有 try/except，MCP 的 `_h`
   与 `mao call` 没有：宿主并发发工具调用时一条异常带走整个会话（表现为工具集体失联）；
   `call` 抛出去则 stdout 只剩崩栈、按行解析 JSON 的脚本拿到空行。两处补齐，口径与 bridge
   一致（`{ok:false,error:类型名+脱敏文案}`）。锚点 M100–M101。
8. **`workers: []` 被折叠成"未点名"** ⇒ 退化成全池轮转派工，与调用方意图相反，还白烧一轮
   额度（vote 是收集+表决两轮）。`_norm_workers` 改为区分"字段缺失"与"显式空"，三个调用点
   对显式空如实报错。锚点 M98。

## 三、P2：健壮性与工程化

- **公共落盘层补跨进程 CAS**：`write()` 原先"锁外读盘 → 锁内合并 → 整篇覆写"，读盘与落盘
  之间被对端插队照样覆盖（同仓 `model_registry.retire_model` 早就用"写前重读比对 + 重试"
  封口，这是第三处）。基类加 `_read_disk_text` 与最多 3 轮的"不一致就整轮重来"；health 的
  `_disk_for_merge` 返回 `(数据, 原始文本)`，并用空串区分"文件还不存在"与"这个账本不做 CAS"
  （首次落盘恰恰最容易被并发覆盖）。锚点 M86。
- **落盘失败不再静默**：`except OSError: pass` 全仓一处日志都没有；Windows 上 `os.replace`
  撞目标被占用是常态（杀毒/索引/另一进程开着），静默等于档案从此不再更新而没人知道。
  `ledger._warn_write_failed` 按路径各点名一次（长驻 bridge 里每轮都刷 stderr 会盖掉真诊断），
  `save_overlay` 复用同一出口。锚点 M87。
- **健康档案两处收口**：`_merge_disk_locked` 并盘时对两侧 `fail_dates` 按元素验类型
  （对端文件混进整数日期会让 `sorted()` 抛 `TypeError`，调用方整段吞异常 ⇒ 隔离静默失效，
  锚点 M89）；账本**键数**封顶 512，裁剪放在"合并 → 序列化"同一次持锁里，内存与落盘文本
  同时封顶（只在记账处裁会被下一步并盘重新灌满，锚点 M88）。发布顺序也定了：`_active` 先赋、
  `_data` 最后发布，快路径只判 `_data is not None` 才名副其实。
- **探测不得吃掉站门**：`_probe_one` 原先 `gate.acquire()` 与 `try/finally release()` 之间
  夹着 `_probe_client_for(p)`（构造 httpx/OpenAI 客户端，非法端点或 SSL 失败都会抛），
  抛一次就永久漏一格 ⇒ 该站此后少一路并发、真实派工排在门上被饿死。改为先建客户端再拿门。锚点 M102。
- **`stop_all` 等后台线程收完**：原先只"叫醒"就返回，进程随即退出、daemon 线程被硬杀，
  stdio 型第三方 server 的子进程留成孤儿。改成先逐个 stop、再共用 5s 预算统一 join。锚点 M103。
- **配置三条口径**：`${VAR}` 解析为空时按"站 + 字段"点名（`_warn_empty_ref`，只报名字不回显值；
  留到运行期就是整站 401，再叠加终态失败连击 7 天会自动去给 git 跟踪的 `model_registry.txt`
  加 `#`，笔误被放大成清单改动，锚点 M104）；`discovery` 改取**插值后**的值，与 note/tags 同一
  口径（旧写法取插值前的 raw，`discovery: ${VAR}` 会把占位符原样当适配器名，静默永不发现，锚点 M105）；
  `.env` 里的小写变量名注入时补同名大写并点名一次（Windows 的 `os.environ` 不区分大小写、
  Linux/CI 区分，同一份 .env 两边行为不一致，锚点 M106）。
- **单一真源**：`llm.timeout`/`llm.max_retries` 只在 `WorkerPool.__init__` 解析一次，建客户端、
  门外重试环、`_effective_timeout` 三处共用（原先批量侧自己再解析一遍，两处对空值/非法值的
  容错口径不一致）；`bridge.reconfigure_streams` 加 `errors="backslashreplace"`（只设 encoding
  不设错误策略时，Windows stderr 默认 strict，一条含 emoji 的诊断就把"写一行日志"变成"整条
  派工被判失败"），serve 循环的 stdout 写入也给了 OSError 出口（留一行 stderr 再退循环）。
- **陈旧说法清理**：`_skip_reason` 还在写"缓存命中不受此限制（ask 里先查缓存）"（LRU 缓存
  早已移除）、`vote` 文档写"附 80 字符预览"（实际是 `vote_preview_chars`，默认 240）。
- **工程化**：`test_repo_hygiene` 的 ruff-exclude 守卫原先 `pytest.importorskip("tomllib")`，
  在 CI 的 3.10 腿上**整条静默跳过**（只有 3.14 那条腿在守）→ 改行级正则，与同文件版本号守卫
  同一先例；`ci.yml` 加 `permissions: contents: read`、两个 job 的 `uv sync` 加 `--frozen`；
  `pyproject.toml` 用 `[[tool.uv.index]] default = true` 把依赖索引钉成 PyPI 并重生成
  `uv.lock`（45 个包、版本零变化，只有下载 URL 从清华镜像换成官方 PyPI）。
- **文档同步**：`docs/外部主接入指南.md` 的"13 条指令"改 14 条并补上缺失的 `refresh_nodes`
  行、工具出口掩码与 `workers: []` 语义、`.env` 说法改为"仓库不带、带全注释模板"、示例响应
  版本号抬到 0.5.0；`docs/架构方案.md` 目录树补齐 10-19 拆出的 4 个模块、删掉自相矛盾的
  `pipeline.py 已实现`与"LRU 缓存已实现"两条；`REQUIREMENTS.md` 变异条目数按**条目**写（99 条，
  标签号到 M106），第七轮记录里"全部 78 项 OK"与"18 条 parametrize"两处口径一并更正并留注。

## 四、本轮的一个操作事故（务必记住）

给 P0 的 `write_file` 守卫写用例时，靶子直接用了项目根的 `.env`。变异门禁 M81 的工作方式
就是**把守卫临时改成失效**来证明用例非恒真 —— 那一刻用例用自己的 `content` 覆盖掉了本机
真实 `.env`（而 `_backup_before_overwrite` 按设计不给密钥文件留档，当场没有回滚点；
`uv lock`/`git` 也救不了，`.env` 不进 git）。

已改：该用例现在只往 pytest 的 `tmp_path` 里放一个假 `.env`（经 `tools.workspace` 授权后才
够得着守卫），并在 docstring 里写下这条规矩 —— **凡是指向"守卫类"修复的用例，只能往
`tmp_path` 里写**。`REQUIREMENTS.md` §9 也加了同一条。事故本身没有造成凭据外泄（旧值是被
覆盖掉的，没被复制到别处），但确实造成了本机配置文件的丢失，需要主人重新填一次。

## 五、变异门禁自己也被这轮修了两处

1. **`subprocess` 没指定编码 → Windows 上解码崩**。`run_pytest`/`node_collects` 用
   `text=True` 却不给 `encoding`，Windows 按本地代码页（cp936）解码子进程输出；一次带
   `PYTHONIOENCODING=utf-8` 的运行直接把 `UnicodeDecodeError: 'gbk' codec can't decode
   byte 0x80` 抛在 subprocess 的 reader 线程里。现在两处都显式 `encoding="utf-8"` +
   `errors="replace"`，并统一给子进程钉 `PYTHONIOENCODING=utf-8`（两侧同一口径，CI 的
   ubuntu 不受影响，只是不再依赖各机器的代码页）。
2. **M106 报 TAUTOLOGY，是用例写歪而不是修复无效**。第一版断言查
   `os.environ["NODE_A_ENDPOINT"]` 是否拿得到值——Windows 的 `os.environ` 不区分大小写，
   即便把"补大写别名"那行变异掉，这个断言照样通过；Linux 上才会红。也就是说这条保护在
   本机是**恒真**的。改法不是删用例，而是把断言落到"我们自己登记的那份记录"上
   （`_dotenv_keys` 是普通 set，不受平台大小写规则影响），并顺手把注入逻辑改成两侧一致：
   "shell 是否已提供大写形态"必须在**写入小写名之前**判断，否则 Windows 上写完再判永远命中，
   别名分支被跳过、两个平台的登记状态不一致。
   ——这条也正是 `ci-ubuntu-platform-neutral-tests` 那条老教训的又一个实例：**本地绿≠CI 绿**，
   凡断言碰到环境变量、路径分隔符、编码、换行，都要问一句"另一侧还成立吗"。

## 六、剔除的误报（子代理报了、核实后不成立）

- **「stdio 型 MCP 子进程继承全量 `os.environ`，第三方 server 白拿整机凭据」**：读了 SDK 源码
  （`.venv/Lib/site-packages/mcp/client/stdio.py:75,128`）——`stdio_client` 用的是
  `get_default_environment() | (server.env or {})`，即一份**安全变量白名单**，
  `env=None` 时根本不继承本进程环境。这条 P1 撤回。
- **「工作树整体 CRLF、需要 renormalize」**：实测 `agent/bridge.py`、`README.md`、
  `agent/core/health.py` 各 0 行含 CR，仓库内跟踪内容也无 CR。误报。

## 七、刻意没动的几条（附理由）

- **`LLMClient.chat()` 与 `_backoff()` 别名**：生产派工走 `chat_once` + 编排层门外重试环，
  这两个只有测试在用。但 conftest 的重试/退避用例正是通过 `chat()` 在验"重试链与退避顺序"，
  删它要连带重写那批用例；`chat()` 的 docstring 已经写明"真实派工不走这里"，
  不构成误导。等真要收敛适配层 API 时一起做。
- **`builtin._WORKSPACE_ROOTS` 是模块级全局**：同进程多个 `Bridge` 会互相覆盖 workspace。
  当前进程模型里一个进程只建一个 Bridge（`__main__`/`mcp_server` 各一），多实例只出现在测试，
  改成挂在 registry/ctx 上要动五个工具函数的取值路径，收益撑不起改动面。
- **技能脚本超时 `SCRIPT_TIMEOUT=120` 仍硬编码**：加 `tools.script_timeout` 要同时动
  config.yaml 骨架、`.env.example` 与两处文档口径（本轮已踩过"删段让 `${VAR}` 变死旋钮"的坑），
  单独开一批做更稳。
- **延迟探测/节点发现的到期调度仍用墙钟**：`_last_start`/`_last_finish` 会随 `latency` 指令
  回显给外部主看，改成 monotonic 后那两个数就失去人类可读意义；要两边都要，得起两套时间戳。
- **超时批次"不收敛"**（只 cancel 未启动的 future、在飞线程无跨批次上限）：这是设计取舍而非
  缺陷——已启动的请求按 `llm.timeout` 自行收尾，加在飞闸门要先定"超限是拒绝还是等待"。
