## 三、P0：三条静默失效

### 1. shell_safety：POSIX shell 家族的内联代码完全不被扫描

- **现象**：`run_shell` 的三层防护（黑名单 → 注入拦截 → 解释器内联代码扫描）对
  `bash -c "rm -rf ~"` 一层都不触发。首词是解释器、破坏藏在正文里，而危险词表是 Windows 向的
  （`rm` 只在正文扫描里生效），`_INTERP_INLINE` 又只收了 python/node/ruby/perl/php/osascript
  这类（`powershell`/`pwsh` 的 `-Command` 有自己那条分支，不在此列）。
- **第二个洞**：只认光秃秃的 `-c`。`bash -lc "..."`（短选项簇）正文位置完全一致却放行。
- **修法**（`agent/tools/shell_safety.py`）：`sh/bash/zsh/dash/ksh` 补进 `_INTERP_INLINE`；
  `_SHELL_CODE_FLAG = re.compile(r"-[a-z]{0,3}c\Z")` 认短选项簇，且**只认单横线**，
  `--norc`（双横线、也以 c 结尾）不会被误判成内联开关。
- **回归**：`tests/test_core.py::test_interpreter_inline_code_guard_blocks_bypass`、
  `::test_posix_shell_inline_guard_blocks_bypass`；变异锚点 M19/M30/M31。

### 2. model_registry._bare_model：把不带 `@` 的模型名切成空串 ⇒ 自动下线形同不存在

- **现象**：`item.lstrip("#").rpartition("@")[0]` 对**没有 `@`** 的条目返回空串
  （`rpartition` 未命中时 `[0]` 是 `''`）。于是"裸模型名"（清单里不带窗口标注的那些，占多数）
  永远匹配不上待下线目标：连续 7 个运行日终态失败的模型，`retire_model` 一路返回 `missing`，
  既不标 `#` 也不报错——上一轮辛苦恢复的自动下线机制，实际上从没为这些模型生效过。
- **修法**：只有当 `@` 之后是上下文长度（纯数字，可带 `k`）时才拆后缀，否则整串即模型名
  （兼容 Cloudflare 的 `@cf/...` 前缀模型名）。与 `config.py` 的解析口径对齐。
- **回归**：`tests/test_audit4_fixes.py::test_retire_model_reports_three_states`（三态契约）+
  `test_health_retire_notice_says_offlined_when_already_marked`；变异锚点 M38。
  **这条是"先写契约测试再回读源码"才暴露的**——测试断言三态，实现却把命中判错。

### 3. skills_manager：单个坏 SKILL.md 炸掉整轮扫描与启动

- **现象**：读取异常（坏编码、权限、目录当文件）逃出整轮 for 循环，一个技能文件让进程起不来。
- **修法**：`except (OSError, ValueError)` 逐条容错，stderr 打 `[技能警告] 跳过无法读取的 …`
  后继续下一个（只报路径与异常类型名，不回显内容）。
- **回归**：`tests/test_core.py::test_skill_scan_survives_bad_encoding`；变异锚点 M41。

## 五、P2：结构性收敛

1. **原子落盘与"同一本账"抽成公共层**（新建 `agent/core/ledger.py`）：`atomic_write_text`
   （临时文件 `名字.pid-threadid.tmp` + `os.replace`）、`AtomicJsonLedger`（`_lock` 记账 /
   `_write_lock` 落盘串行）、`shared_by_path`（同路径进程内共享实例）。`ModelHealth` 与
   `LatencyStore` 都改为继承它——此前"快照取在写锁之外"的 lost update 在两个模块各修过一遍
   （`e2c8573` / `57c6826`），收敛后不可能再各写一套。
   - 不变式：**取快照与写盘同在 `_write_lock` 内串行**（写盘顺序必须等于快照顺序），
     **文件 IO 一律在 `_lock` 之外**（热路径 `quarantined()` / `get_ms()` 不能被落盘卡住）。
   - 回归做成**确定性探针**而不是计时断言：包一层 `_snapshot_locked`，进去后用非阻塞
     `acquire(blocking=False)` 探 `_write_lock` 是否被持有。参数化 `[health|latency]`，
     Windows 与 CI 都不抖。见 `test_snapshot_is_taken_inside_the_write_lock`；锚点 M17/M33/M1/M2/M23。
2. **时钟域**：冷却时限改用 `time.monotonic()`（`_is_in_cooldown` / `_record_result`），
   NTP 校时或手动改表不再能提前解除冷却；`time.time()` 只留给持久化的日期戳（跨天隔离按日历日）。
   回归 `test_cooldown_is_immune_to_wall_clock_jump`（monkeypatch 模块内的 `time` 引用，
   不碰全局 `time.time`，免得影响 pytest 自己的计时）；锚点 M36。
3. **dotenv 解析顺序**：引号处理必须**先于** ` #` 注释剥离，否则 `KEY="a # b"` 里的 `#` 被当注释切掉；
   同时改成单次解析（不再先剥注释再剥引号地来回两遍）。回归 `test_dotenv_keeps_hash_inside_quotes`；锚点 M34。
4. **死代码与重复口径**：删 `config.CONTEXT_SAFETY`（无引用）、`health._already_retired`
   （与 `retire_model` 三态重复）、`bridge.py` 拆兜底后遗留的 `Lock` import、
   `test_config_contract.py` 的 `Config` import；`retire_model` 的三态常量只留一份。
5. **工程缺口**：
   - 新建 `.env.example`：只列变量名、每行注释掉、写清优先级与"留成 `KEY=` 空串会顶掉
     `config.yaml` 的 `:-默认值`"这个坑；模型清单明确不属于它。`tests/test_repo_hygiene.py`
     守三件事：模板不得带值、模板里的变量名不得失效、`config.yaml` 引用的端点/密钥类变量不得漏列。
   - CI：`python: ["3.10", "3.14"]` 双版本矩阵（下限此前从未被验证）+ `ruff format --check`
     门禁（排在 lint 之前）+ 独立 `mutation-gate` job。
   - 测试盲区：补 `bridge` / `mcp` / `call` 三条外壳的 CLI 子进程用例（stdout 按 UTF-8 **严格解码**
     读协议行——Windows 重定向会落 GBK 字节，宽松解码会把乱码当正常）。
   - 变异门禁：锚点是字面源码片段，重构/format 后失配打 SKIP 且**计入失败**；本轮重指被 format
     冲散的 M1/M2/M23/M30，并新增 M30–M43，共 37 项全为有效断言。

## 六、审计过程中顺带发现并处置的一处配置回归

`llm:` 段被整段删除（拆兜底单模型）后，`config.yaml` 不再引用 `${LLM_TIMEOUT}` /
`${LLM_MAX_RETRIES}`，代码退回 `llm_cfg.get("timeout", 120)` ⇒ **环境变量变成死旋钮**：设了不生效、
也不报错，而 `docs/外部主接入指南.md` 仍在教外部主"抬 `ask_many` 超时就用 `LLM_TIMEOUT`"。

处置：`config.yaml` 保留一个只含 `timeout` / `max_retries` 的 `llm:` 段（都带 `:-` 默认，不配也能跑），
`REQUIREMENTS.md` §8 用一行说明"该段只剩调用参数、不含兜底模型"。实测 `LLM_TIMEOUT=300` 时
`cfg.llm_cfg == {'timeout': '300', 'max_retries': '2'}`，文档口径重新成立。

`temperature` **没有**跟着恢复引用：代码里没有任何地方读它（`LLMClient` 用形参默认 0.7），
恢复 `${LLM_TEMPERATURE}` 只会制造"可配"的错觉。
